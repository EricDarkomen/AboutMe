Personal project · v1.24

LeanOS

An operations suite for lean & operational excellence · runs in the browser, no server

Most operations run continuous improvement across a dozen disconnected spreadsheets, a whiteboard and a shared drive nobody trusts. LeanOS is one connected suite instead: sixty-one tools covering what an operation actually runs on — the daily SQCDP board, 5S audits, OEE, SMED, value-stream maps, FMEA, 8D and A3 — wired to an order book, a stock ledger, payroll and a real set of books.

Every tool writes to one local store and feeds one maturity score, so a number on the dashboard is one hop from the cause behind it. It runs entirely in the browser on an OPFS-backed SQLite engine: no account, no server, and no data leaving the device unless you export it.

This is the project where the two halves of my CV meet — twenty-five years of operations and continuous improvement on one side, and the software to run it on the other.

Built on the domain, not around it

SQCDP, OEE, SMED, Bradford scores, OTIF, first-pass yield, cost of poor quality. I have worked with these on a real floor, which is why the tools ask the questions a supervisor actually asks rather than the ones that are easy to build.

Local-first, deliberately

An improvement team cannot wait for an IT project. Everything lives in the browser on SQLite over OPFS — open the file and it runs. Where a browser can’t offer a durable store, the app says so rather than pretending.

One thread, prospect to cash

An opportunity becomes a costed quote, a credit-checked sales order, a work order that draws its own bill of materials, a shipment, an invoice — and posts into the ledger, the VAT return and the cash forecast. Scrap lands in Cost of Quality on the way through.

The repository is private. I’m happy to walk through it or demonstrate it — it needs nothing but a browser.

Four decisions worth explaining

No build step, on purpose

Modern JavaScript modules are fetched, and a page opened off a local disk is not allowed to fetch. Plain scripts are loaded. So the game opens from a folder with no server, no install and no toolchain — and the test suite proves it on every run.

The tests drive a real browser

Twenty-three suites in headless Chromium, across phones and desktops. They caught faults nothing else would: a set of Christmas decorations that sealed a room off, and a waypoint placed on a sink that walked staff into the basin.

Validation where the work happens

The editor runs ten cross-file checks as you type — a job pointing at furniture that has been moved, dialogue nobody can reach, a reward nothing can hand out. The class of fault that is invisible on screen and expensive later.

Licence enforced by the build

The artwork is third-party. The sprite build reads each asset’s upstream licence data and refuses to produce a sheet if anything falls outside the permitted terms. Compliance is a check that fails, not a note in a file.
